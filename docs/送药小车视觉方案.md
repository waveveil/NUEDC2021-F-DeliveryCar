# 2021 年电赛 F 题送药小车视觉方案

## 1. 目标

视觉系统完成以下去程任务：

1. 小车启动前识别手持的单张病房卡牌，稳定锁定目标病房号 `1～8`。
2. 收到底盘单片机的开始指令后进入行驶状态。
3. 行驶过程中持续输出巡线数据，并提前缓存路口附近的数字识别结果。
4. 检测到路口后，根据目标数字位于道路中心左侧还是右侧，输出左转或右转指令。
5. 如果方向无法可靠确认，要求底盘减速或停车，继续识别，不能猜测方向。
6. 一个路口只触发一次方向指令；底盘完成转弯后回传完成事件，视觉系统再重新准备识别下一个路口。

本阶段先打通去程视觉链路。返程路线记录、到达病房和掉头流程留出接口，等去程实测稳定后再实现。

## 2. 系统职责

### 2.1 MaixCAM

- 只创建一个摄像头和一个主循环。
- 运行 YOLOv8 数字识别。
- 运行道路巡线检测。
- 运行十字路口检测。
- 完成目标卡牌多帧锁定。
- 完成数字排列、左右位置和多帧方向投票。
- 通过 UART 向底盘单片机发送巡线数据、目标病房号、转弯方向和视觉异常状态。

### 2.2 底盘单片机

- 接收视觉侧的巡线误差和方向指令。
- 完成电机速度闭环、循迹闭环和转弯动作。
- 向 MaixCAM 发送开始、停止、重置和转弯完成事件。
- 收到视觉无法确认方向的状态后减速或停车。

视觉侧不直接控制电机，底盘侧不负责识别数字。

## 3. 单摄像头架构

数字识别、巡线和路口检测不能各自打开摄像头。总控程序每帧只采集一次图像：

```text
摄像头读取一帧
      │
      ├── 原始模型尺寸图像 → YOLOv8 数字检测
      │
      └── RGB 320×240 图像
              ├── 巡线检测
              └── 路口检测
                       │
                       ▼
                    状态机
                       │
                       ▼
                 UART → 底盘单片机
```

摄像头的尺寸和格式由 YOLO 模型的 `input_width()`、`input_height()` 和 `input_format()` 决定。巡线和路口检测使用转换后的 RGB `320×240` 图像。

所有用于跨分辨率比较的横坐标都转换为 `0～1` 的归一化坐标，避免直接比较 YOLO 图像坐标和 `320×240` 图像坐标。

## 4. 去程状态机

```text
CAPTURE_TARGET
      │ 稳定识别目标卡牌
      ▼
WAIT_START
      │ 收到 START
      ▼
FOLLOW_LINE
      │ 连续确认路口
      ▼
DECIDE_DIRECTION
      ├── 方向可靠 → 发送一次 LEFT/RIGHT
      │                    ▼
      │              WAIT_TURN_DONE
      │                    │ 收到 TURN_DONE 且路口消失
      │                    └──────────→ FOLLOW_LINE
      │
      └── 方向不可靠 → 发送 VISION_HOLD，停车继续识别

任意状态收到 RESET → CAPTURE_TARGET
任意行驶状态收到 STOP → WAIT_START
```

### 4.1 `CAPTURE_TARGET`

- 只接受目标卡牌 ROI 内的数字。
- 只接受 `1～8`。
- 使用最近若干帧投票，不使用单帧结果。
- 同时出现多个不同数字时不锁定。
- 锁定后发送 `TARGET_LOCKED`，除非收到 `RESET`，否则不再修改目标。

### 4.2 `WAIT_START`

- 显示已经锁定的病房号。
- 清空路口和方向投票历史。
- 等待底盘单片机发送 `START`。

### 4.3 `FOLLOW_LINE`

- 每帧运行巡线检测并发送巡线误差。
- 每帧或按配置间隔运行路口检测。
- YOLO 按配置间隔运行，提前缓存目标数字在道路中心左侧或右侧的投票。
- 不等小车完全进入路口后才开始识别数字。

### 4.4 `DECIDE_DIRECTION`

- 优先使用已经确认的路口中心作为左右分界。
- 路口中心暂时不可用时，使用巡线估算的道路中心。
- 两者都不可用时，最后才使用标定后的画面中心。
- 方向票不足、左右冲突或目标在死区内时，发送 `VISION_HOLD`，要求底盘停车继续采样。

### 4.5 `WAIT_TURN_DONE`

- 方向一旦确定，只发送一次转弯事件。
- 暂停对新路口作决策。
- 等待底盘回传 `TURN_DONE`。
- 只有当前路口连续消失后才重新武装，防止同一路口重复触发。

## 5. 数字检测数据格式

YOLO 模块只负责输出检测结果，不直接决定方向：

```python
{
    "number": 5,
    "class_id": 4,
    "score": 0.87,
    "x": 40,
    "y": 60,
    "w": 30,
    "h": 45,
    "cx": 55.0,
    "cy": 82.5,
    "cx_norm": 0.172,
    "cy_norm": 0.344,
}
```

数字值必须从模型标签解析，不能假设 `class_id` 一定等于病房号。

## 6. 两数字和四数字的判断

### 6.1 先筛选同一行

背景中可能存在其他数字，因此不能把整幅图的所有检测框直接排序。应当：

1. 过滤病房号范围外、置信度过低和尺寸异常的框。
2. 合并同一数字的重复框。
3. 根据数字框中心纵坐标和框高，将检测框分组为一行或多行。
4. 选择数量合理、总置信度最高且位置符合数字标志 ROI 的一行。
5. 将选中行按中心横坐标从左到右排序。

### 6.2 排列解释

```text
四数字：[7, 5, 6, 8]
          └左侧┘ └右侧┘

两数字：[3, 4]
          左  右
```

完整识别到两个或四个数字可以提高场景可信度，但不能作为唯一决策条件。小车运动时可能只识别到一个或三个数字；只要目标数字的位置经过多帧确认，仍可决定方向。

### 6.3 左右判断

```text
offset = target.cx_norm - road_center_x_norm

offset < -dead_zone → LEFT
offset >  dead_zone → RIGHT
其他情况           → UNKNOWN
```

道路中心的优先级：

1. 已确认的路口中心。
2. 巡线算法得到的道路中心。
3. 标定后的画面中心。

## 7. 容错方案

### 7.1 目标卡牌多帧锁定

- 保存最近若干帧的候选数字。
- 达到最低票数后才锁定。
- 低置信度帧记为无效，不强行参与投票。
- 锁定后只有 `RESET` 可以清除。

### 7.2 方向多帧加权投票

- 目标在左侧时累加左侧置信度，在右侧时累加右侧置信度。
- 目标缺失或落在中间死区时不投票。
- 有效帧数量、胜方总分和左右分差必须同时达到阈值。
- `3:2` 等接近结果不立即决策；明显占优后才锁定方向。

### 7.3 重复框过滤

- 同类别且 IoU 很高时只保留置信度最高的框。
- 同类别且中心距离很近时只保留一个框。
- YOLO 已执行 NMS，但决策层仍保留轻量去重，防止重复结果影响数字数量。

### 7.4 按行过滤

- 同一行数字的中心纵坐标应该接近。
- 框高应大致相近。
- 优先选择总置信度高、数量为 `2～4` 的一行。
- 数字数量为 `1` 或 `3` 时不直接判错，可以继续进行目标位置投票。

### 7.5 左右死区

目标框离道路中心过近时返回 `UNKNOWN`，避免摄像头抖动导致左右结果反复切换。死区初值可设置为图像宽度的 `5%～10%`，最终按实车画面标定。

### 7.6 无法确认时停车

遇到以下情况时发送 `VISION_HOLD`：

- 目标数字长期检测不到。
- 目标数字落在中心死区。
- 左右票数冲突。
- 路口已经确认，但方向票仍不足。
- 1、2 号当前路口超出固定路线配置，或配置方向无效。

停车后继续采集若干帧；仍无法确认则保持停车并上报状态，绝不默认左转或右转。

### 7.7 路口去重

```text
未检测到路口
→ 连续检测到路口
→ 路口确认并锁存
→ 方向确定
→ 等待转弯完成
→ 路口连续消失
→ 允许识别下一个路口
```

### 7.8 同帧一致性

总控模式关闭 YOLO `dual_buff`，保证数字结果对应当前输入帧。独立模型调试时可以开启双缓冲提高帧率。

## 8. 黑线与红线支持

系统通过配置选择：

```python
LINE_COLOR = "black"
# 或
LINE_COLOR = "red"
```

- 路口检测：正式 V2 使用四个 ROI 和 MaixPy `find_blobs()` 的 LAB 阈值。
- 巡线检测：同样使用 MaixPy `find_blobs()` 的 LAB 阈值；黑线沿用当前参数，红线先提供参考初值。
- 阈值只作为初值。赛道材料、灯光、曝光和相机角度变化后，必须在现场重新标定。

## 9. UART 协议设计

统一帧格式：

```text
AA 55 LEN TYPE PAYLOAD CHECKSUM
```

- `AA 55`：帧头。
- `LEN`：`TYPE + PAYLOAD` 的总长度。
- `TYPE`：消息类型。
- `PAYLOAD`：消息数据，小端编码。
- `CHECKSUM`：从帧头到 payload 末尾的字节累加和低 8 位。

### 9.1 STM32 → MaixCAM

- `START`：开始去程。
- `STOP`：安全停止并返回等待状态。
- `RESET`：清空目标和全部视觉状态，重新识别卡牌。
- `TURN_DONE`：底盘已经完成当前转弯。

### 9.2 MaixCAM → STM32

- `TARGET_LOCKED`：目标病房号已经稳定锁定。
- `LINE_DATA`：巡线是否有效、横向误差、道路角度和道路中心。
- `TURN_DECISION`：左转或右转，仅发送一次事件。
- `VISION_HOLD`：方向不可靠，请减速或停车。
- `STATUS`：当前视觉状态和故障信息。

接收端必须支持半包、粘包、帧头前噪声和错误校验恢复。

## 10. 1、2 号病房与返程

### 10.1 固定病房

1、2 号病房使用固定路线配置表。当前代码暂按 1 号首个路口左转、2 号首个路口右转配置，必须在实际赛道上复核；目标为 1 或 2 且当前路口查不到可靠方向时发送 `VISION_HOLD`，不猜方向。

### 10.2 返程预留

去程每次转弯可在后续版本记录到路线栈。返程时逆序读取，左转和右转互换，直行保持不变。由于到达病房、卸药、掉头和返程开始事件尚未定义，本阶段不写不完整的返程状态机。

## 12. MaixPy API 约束

实现时以仓库内 `MaixPy-main/MaixPy-main` 的源码、文档和示例为准：

- `nn.YOLOv8.detect(img, conf_th=..., iou_th=...)` 返回带 `x/y/w/h/class_id/score` 的对象。
- `Image.resize()` 返回新图像，原图不变。
- `Image.to_format()` 返回新格式图像，原图不变。
- `image.image2cv(..., copy=False)` 共享图像内存，引用有效期内不能销毁原图。
- `UART.read()` 默认非阻塞，无数据时返回空字节。
- `find_blobs()` 阈值使用 `[[L_MIN, L_MAX, A_MIN, A_MAX, B_MIN, B_MAX]]`。

### 14.2 启动过程

运行 `delivery_car_main.py` 后：

1. `DigitDetector(dual_buff=False)` 加载 `/root/models/yolov8_num_detect_v2.mud`。关闭双缓冲，保证数字结果与本次送入模型的画面同步。
2. 创建 `LineTracker(LINE_COLOR)` 和 `CrossroadDetector(LINE_COLOR)`。
3. 创建 `TargetLocker`、`DirectionVoter`、`DeliveryStateMachine` 和 UART `FrameParser`。
4. 将 A19 映射为 `UART1_TX`、A18 映射为 `UART1_RX`，以 `115200` 打开 `/dev/ttyS1`。
5. 使用 YOLO 模型输入宽、高和格式创建唯一摄像头，帧率初值为 `30`。
6. 创建显示器，状态机初始为 `CAPTURE_TARGET`，发送对应 `STATUS` 帧。

### 14.3 每帧主循环

`DeliveryController.process_frame()` 每次按以下顺序执行：

1. 非阻塞调用 `UART.read()`，把新字节交给 `FrameParser`。
2. 处理所有完整有效的 `START/STOP/RESET/TURN_DONE` 帧。
3. 调用一次 `cam.read()` 得到 `model_img`。
4. 原图保持模型要求的尺寸和格式，供 YOLO 使用。
5. 如果原图不是 RGB，调用 `to_format(FMT_RGB888)`；如果不是 `320×240`，再调用 `resize(320, 240)`，得到 `vision_img`。
6. `CAPTURE_TARGET` 和 `DECIDE_DIRECTION` 状态每帧运行 YOLO；其他状态默认每两帧运行一次。
7. 根据当前状态执行目标锁定，或执行巡线、路口检测和方向投票。
8. 默认每两帧刷新一次屏幕，显示状态、目标号、线色、巡线、路口、左右票和最近 UART 事件。
9. 循环末尾 `sleep_ms(1)` 释放少量 CPU 时间。

### 14.4 目标卡牌锁定

处于 `CAPTURE_TARGET` 时：

1. YOLO 结果由 `DigitDetector.detect()` 转成普通字典。
2. 标签只有能明确解析为单个 `1～8` 数字时才保留。
3. `TargetLocker` 只接受归一化 ROI `(0.20, 0.10, 0.80, 0.90)` 内的候选框。
4. 一帧中必须恰好剩一个候选数字，否则该帧记为无效。
5. 默认最近 7 帧中同一数字至少得到 5 票，并比第二名至少多 2 票，才锁定目标。
6. 锁定后状态切换到 `WAIT_START`，依次发送 `TARGET_LOCKED` 和 `STATUS`。
7. `WAIT_START` 不运行巡线和路口检测，也不发送巡线控制量，只等待 `START` 或 `RESET`。

### 14.5 开始和正常巡线

收到有效 `START` 后：

1. 状态从 `WAIT_START` 切换到 `FOLLOW_LINE`。
2. 清空方向投票，重置巡线滤波和路口连续帧计数。
3. 发送新的 `STATUS`。
4. 每帧调用 `LineTracker.process(vision_img)` 和 `CrossroadDetector.process(vision_img)`。
5. 默认每两帧发送一次 `LINE_DATA`，但只在 `FOLLOW_LINE` 或 `DECIDE_DIRECTION` 状态发送；底盘转弯期间不再发送巡线控制量。

巡线结果同时包含两个中心：

- `center_x_norm`：道路中心线在画面底部的位置，供底盘横向纠偏数据使用。
- `decision_center_x_norm`：拟合道路中心线在上方 ROI 的位置，供远处数字左右判断使用。

### 14.6 数字方向投票

目标为 `3～8` 时，YOLO 每次得到结果后：

1. 丢弃低于 `0.45`、范围不在 `1～8`、尺寸无效或归一化坐标无效的框。
2. 同类别框 IoU 大于等于 `0.55`，或归一化中心距离小于等于 `0.035` 时，只保留高置信度框。
3. 按中心纵坐标分组，选择总置信度最高的一行；数量为 `2～4` 的行有额外优先级。
4. 在所选行中寻找目标病房号。
5. 左右分界优先取当前确认的路口中心，其次取巡线上方决策中心，最后取配置值 `0.50`。
6. 目标与分界的距离不超过 `0.07` 时进入死区，该帧不投票。
7. 目标在左/右时，将检测置信度累加到相应方向。
8. 默认最近 8 个样本中至少需要 4 个有效样本；胜方分数至少 `2.2`，并且领先另一方至少 `0.8`，才形成最终方向。

因此，完整看到两个或四个数字有利于正确选择数字行，但并不是决策的强制条件。

### 14.7 路口和转弯流程

1. `CrossroadDetector` 当前使用 `crossroad_detect_v2.py` 的四 ROI、`find_blobs()` 色块选择、两线拟合和交点筛选算法。
2. 连续 3 帧检测到交点后，`confirmed=True`。
3. 只有当前帧仍然存在交点并且状态机已经武装时，才从 `FOLLOW_LINE` 进入 `DECIDE_DIRECTION`。
4. 进入后先发送 `DECIDE_DIRECTION` 对应的 `STATUS`。
5. 如果方向票已经足够，状态机锁定 `LEFT` 或 `RIGHT`，发送一次 `TURN_DECISION`，随后进入 `WAIT_TURN_DONE` 并发送新 `STATUS`。
6. 如果方向不足，只发送一次 `VISION_HOLD`，要求底盘停车；YOLO 保持每帧运行，方向可靠后仍可继续发送转弯决策。
7. `WAIT_TURN_DONE` 中继续观察画面，但不发送新的巡线包，也不接受同一路口的新方向触发。
8. 收到有效 `TURN_DONE` 后回到 `FOLLOW_LINE`，清空方向票和路口检测计数，但保持路口未武装。
9. 当前路口连续 3 帧消失后才重新武装，允许下一个路口触发。

### 14.8 1、2 号固定路线

`delivery_car_main.py` 中当前配置为：

```python
FIXED_ROUTES = {
    1: [LEFT],
    2: [RIGHT],
}
```

当前配置表示目标为 1 号时在第 0 个路口左转，目标为 2 号时在第 0 个路口右转；必须根据实际赛道确认。如果当前路口索引超出配置列表，总控发送原因码为 `3` 的 `VISION_HOLD`，不默认转向。以后可以按实际去程路口顺序填写，例如 `[LEFT]` 或 `[RIGHT, LEFT]`。

### 14.9 UART 精确格式

帧结构：

```text
AA 55 LEN TYPE PAYLOAD CHECKSUM
```

`LEN` 等于 `TYPE + PAYLOAD` 的字节数，当前允许 `1～64`；校验和为前面所有字节累加和的低 8 位。

STM32 发给 MaixCAM 的消息当前 payload 均为空：

| TYPE | 值 | 含义 |
| --- | --- | --- |
| `START` | `0x01` | 从 `WAIT_START` 进入 `FOLLOW_LINE`。 |
| `RESET` | `0x02` | 清空目标、滤波、投票、路口和协议缓存，回到 `CAPTURE_TARGET`。 |
| `STOP` | `0x03` | 保留已锁定目标时回到 `WAIT_START`，否则回到 `CAPTURE_TARGET`。 |
| `TURN_DONE` | `0x04` | 只在 `WAIT_TURN_DONE` 中有效。 |

MaixCAM 发给 STM32：

| TYPE | 值 | payload 小端格式 |
| --- | --- | --- |
| `TARGET_LOCKED` | `0x81` | `<B`：目标病房号。 |
| `LINE_DATA` | `0x82` | `<BhhH`：valid、横向误差像素、角度×100、底部中心归一化值×1000。 |
| `TURN_DECISION` | `0x83` | `<BBBB`：方向、目标号、当前路口序号、方向票置信度百分比。 |
| `VISION_HOLD` | `0x84` | `<B`：原因码；当前 `2=方向不确定`，`3=固定路线未配置`。 |
| `STATUS` | `0x85` | `<BB`：状态码、detail；当前 detail 为 0。 |

方向值：`0=LEFT`，`1=RIGHT`。状态值：

```text
1 = CAPTURE_TARGET
2 = WAIT_START
3 = FOLLOW_LINE
4 = DECIDE_DIRECTION
5 = WAIT_TURN_DONE
```

路口序号从 0 开始，发送成功后加 1；它可用于 STM32 过滤重复或记录路线。
