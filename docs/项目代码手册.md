# 1. 项目文件总览

## 1.1 正式运行链路

| 文件 | 作用 | 正式总控是否使用 |
| --- | --- | --- |
| `delivery_car_main.py` | 整车视觉总控、状态机调度、UART 收发 | 是，正式入口 |
| `delivery_logic.py` | 数字去重、数字行筛选、目标锁定、方向投票、状态机 | 是 |
| `vision_protocol.py` | UART 帧编码和流式接收解析 | 是 |
| `yolov8_num_detect.py` | YOLOv8 数字检测，输出数字框数据 | 是 |
| `track_line.py` | 黑线/红线巡线，输出偏差和道路中心 | 是 |
| `crossroad_detect_v2.py` | 黑线/红线十字路口检测，输出交点 | 是 |
| `test_delivery_logic.py` | 电脑端纯逻辑单元测试 | 不在小车运行时使用 |

## 1.2 参考或实验文件

| 文件 | 作用 | 注意事项 |
| --- | --- | --- |
| `crossroad_detect.py` | 使用 OpenCV、颜色掩膜和 Hough 线段检测十字路口的参考版本 | 正式总控当前不导入 |
| `num_detact.py` | 旧的 MNIST 单数字分类方案 | 正式总控当前不导入 |

| `MaixPy-main/` | MaixPy 源码、文档和官方示例 | 用于核对 API |

## 1.3 正式调用关系

```text
delivery_car_main.py
│
├── yolov8_num_detect.py

```

# 2. 一帧图像如何被处理

总控每轮只执行一次 `cam.read()`：

```text
model_img = cam.read()
       │
       ├── 原尺寸、原格式 → YOLOv8 数字检测
       │
       └── 转 RGB 并缩放到 320×240 → vision_img
                                      ├── LineTracker.process()
                                      └── CrossroadDetector.process()
```

这样避免三个模块分别打开摄像头，也保证三个模块处理的是同一时刻附近的画面。

## 2.1 两套坐标

项目存在两套图像尺寸：

- `model_img`：由 YOLO 模型决定宽、高和格式。
- `vision_img`：固定 RGB `320×240`，供巡线和路口检测。

跨模块比较位置时使用归一化坐标：

```text
x_norm = x / image_width
y_norm = y / image_height
```

归一化范围一般是 `0.0～1.0`，因此即使模型输入不是 `320×240`，也可以比较数字中心、道路中心和路口中心。

# 3. `delivery_car_main.py`：正式总控

## 3.1 文件职责

这个文件是正式运行入口，负责：

- 初始化 YOLO、摄像头、显示器和 UART。
- 初始化巡线、路口、投票和状态机。
- 每帧调度不同视觉模块。
- 接收 STM32 的开始、停止、重置和转弯完成指令。
- 发送目标号、巡线数据、转向方向、暂停请求和状态。
- 控制同一路口只触发一次转弯。

正式运行：

```bash
python delivery_car_main.py
```

## 3.2 顶层配置变量

### `LINE_COLOR`

```python
LINE_COLOR = "black"
```

选择道路中心线颜色：

- `"black"`：黑线。
- `"red"`：红线。

该值会同时传给 `LineTracker` 和 `CrossroadDetector`。

### `CAM_FPS`

```python
CAM_FPS = 30
```

请求摄像头以 30 FPS 工作。实际总处理帧率还会受 YOLO、OpenCV、显示和 UART 影响。

### `YOLO_EVERY_N_FRAMES`

```python
YOLO_EVERY_N_FRAMES = 2
```

在普通行驶状态下每 2 帧运行一次 YOLO。

- 减小：数字响应更快，但算力消耗更大。
- 增大：帧率可能提高，但数字投票速度下降。
- `CAPTURE_TARGET` 和 `DECIDE_DIRECTION` 状态不受该间隔限制，每帧运行 YOLO。

### `DISPLAY_EVERY_N_FRAMES`

```python
DISPLAY_EVERY_N_FRAMES = 2
```

每 2 帧刷新一次屏幕。显示会消耗性能，比赛时可以增大或关闭显示。

### `LINE_PACKET_EVERY_N_FRAMES`

```python
LINE_PACKET_EVERY_N_FRAMES = 2
```

每 2 帧发送一次巡线包。

### UART 配置

```python
UART_DEVICE = "/dev/ttyS1"
UART_BAUDRATE = 115200
```

当前使用 MaixCAM UART1：

- A19：TX。
- A18：RX。
- 波特率：115200。

### `TARGET_ROI`

```python
TARGET_ROI = (0.20, 0.10, 0.80, 0.90)
```

启动卡牌的归一化有效区域，格式为：

```text
(x_min, y_min, x_max, y_max)
```

当前接受画面横向 20%～80%、纵向 10%～90% 范围内的卡牌。

如果手持卡牌经常不在框内，可以扩大；背景数字容易进入时，可以缩小。

### `DEFAULT_CENTER_X_NORM`

```python
DEFAULT_CENTER_X_NORM = 0.50
```

路口中心和巡线中心都不可用时，数字左右判断使用的最后备用分界线。`0.50` 表示画面中心。

如果摄像头安装明显偏向一侧，可以现场标定为其他值。

### `FIXED_ROUTES`

当前代码实际配置为：

```python
FIXED_ROUTES = {
    1: [LEFT],
    2: [RIGHT],
}
```

表示：

- 目标为 1 号时，第 0 个路口左转。
- 目标为 2 号时，第 0 个路口右转。

列表下标就是 `intersection_index`。例如：

```python
1: [LEFT, RIGHT]
```

表示去 1 号时第一个路口左转，第二个路口右转。

这里必须根据实际赛道确认。如果当前赛道方向不是这样，应立即修改。

### `STATE_CODES`

把字符串状态映射成 UART 中的整数：

```text
CAPTURE_TARGET  → 1
WAIT_START      → 2
FOLLOW_LINE     → 3
DECIDE_DIRECTION→ 4
WAIT_TURN_DONE  → 5
```

STM32 可以根据这些值知道视觉系统当前处于什么阶段。

## 3.3 普通函数

### `setup_uart()`

**作用：** 配置 UART1 引脚并创建 UART 对象。

**参数：** 无。

**执行：**

1. A19 映射为 `UART1_TX`。
2. A18 映射为 `UART1_RX`。
3. 打开 `/dev/ttyS1`，波特率 115200。

**返回值：**

```python
uart.UART
```

返回 MaixPy UART 对象。

**可能异常：** 引脚映射失败时 `err.check_raise()` 会抛出异常。

---

### `prepare_vision_image(img)`

**作用：** 将模型摄像头图像转换成巡线和路口模块要求的 RGB `320×240` 图像。

**参数：**

- `img`：`maix.image.Image`，通常是 `cam.read()` 得到的模型图像。

**处理流程：**

1. 如果不是 `FMT_RGB888`，调用 `to_format()`。
2. 如果尺寸不是 `320×240`，调用 `resize()`。

**返回值：**

```python
maix.image.Image
```

返回 RGB `320×240` 图像；如果原图已经满足要求，可能直接返回原对象。

---

### `direction_confidence(voter, direction)`

**作用：** 把方向投票分数转换成 `0～100` 的百分比。

**参数：**

- `voter`：`DirectionVoter` 实例。
- `direction`：`LEFT` 或 `RIGHT`。

**计算：**

```text
指定方向分数 / 左右总分 × 100
```

**返回值：** 整数百分比。无有效票或方向无效时返回 `0`。

**注意：** 固定路线没有视觉方向票，因此 1、2 号的该值通常为 0；它不表示固定路线错误。

---

### `draw_target_roi(img)`

**作用：** 在启动识别画面上绘制目标卡牌有效区域。

**参数：**

- `img`：显示用图像。

**返回值：** 无。直接修改图像对象。

---

### `draw_status(img, machine, line_result, cross_result, voter, last_uart_event)`

**作用：** 在画面上显示调试状态。

**参数：**

- `img`：显示图像。
- `machine`：`DeliveryStateMachine`。
- `line_result`：巡线结果字典。
- `cross_result`：路口结果字典。
- `voter`：方向投票器。
- `last_uart_event`：最近接收到或生成的 UART 事件文本。

**显示内容：**

- 状态、目标号、线色。
- 巡线是否有效。
- 路口是否确认。
- 左右票数和分数。
- 最近 UART 事件。

**返回值：** 无。

## 3.4 `DeliveryController` 类

这是总控的核心类。

### `DeliveryController.__init__()`

**作用：** 初始化全部模块和硬件。

**创建的关键成员变量：**

| 成员 | 类型 | 作用 |
| --- | --- | --- |
| `digit_detector` | `DigitDetector` | YOLO 数字检测，正式总控关闭双缓冲 |
| `line_tracker` | `LineTracker` | 巡线检测 |
| `crossroad_detector` | `CrossroadDetector` | 路口检测 |
| `target_locker` | `TargetLocker` | 启动卡牌多帧锁定 |
| `direction_voter` | `DirectionVoter` | 行驶中左右方向投票 |
| `machine` | `DeliveryStateMachine` | 去程状态机 |
| `parser` | `FrameParser` | UART 字节流解析器 |
| `uart_dev` | `uart.UART` | UART1 对象 |
| `cam` | `camera.Camera` | 唯一摄像头对象 |
| `disp` | `display.Display` | 显示对象 |
| `frame_index` | `int` | 总帧编号，用于降频执行 |
| `intersection_index` | `int` | 已决定方向的路口序号，从 0 开始 |
| `last_uart_event` | `str` | 最近 UART 事件，用于显示 |
| `last_detections` | `list` | 最近一次 YOLO 结果 |
| `last_line_result` | `dict` | 最近巡线结果 |
| `last_cross_result` | `dict` | 最近路口结果 |
| `hold_sent` | `bool` | 当前不确定状态是否已经发送过暂停包 |

**返回值：** 构造函数无显式返回值。

---

### `DeliveryController.reset()`

**作用：** 把整个视觉流程恢复到重新识别目标卡牌的状态。

**清空内容：**

- 状态机和目标号。
- 目标投票、方向投票。
- 巡线滤波。
- 路口连续帧计数。
- UART 接收缓存。
- 路口序号。
- 最近检测结果和暂停锁存。

**返回值：** 无。

---

### `DeliveryController.send(packet)`

**作用：** 发送已经编码好的 UART 帧。

**参数：**

- `packet`：`bytes`。

**返回值：** 无。内部调用 `self.uart_dev.write(packet)`。

---

### `DeliveryController.send_state()`

**作用：** 把当前状态机状态编码为 `STATUS` 帧并发送。

**参数：** 无。

**返回值：** 无。

---

### `DeliveryController.receive_uart()`

**作用：** 非阻塞读取 UART，并处理所有完整指令。

**输入：** 无显式参数，从 `self.uart_dev.read()` 读取字节。

**支持的指令：**

- `RESET`：调用总控 `reset()`，回到目标识别。
- `STOP`：保留目标时回到 `WAIT_START`。
- `START`：只有 `WAIT_START` 状态可进入 `FOLLOW_LINE`。
- `TURN_DONE`：只有 `WAIT_TURN_DONE` 状态可结束当前转弯。

**返回值：** 无。

**副作用：** 可能改变状态、清空投票、重置检测器并发送状态包。

**当前注意点：** `payload` 被解析出来但这些控制指令暂时没有检查 payload 内容。

---

### `DeliveryController.update_target(detections)`

**作用：** 将当前数字检测结果送入目标锁定器。

**参数：**

- `detections`：`DigitDetector.detect()` 返回的列表。

**行为：**

- 未达到稳定票数时不操作。
- 锁定后让状态机进入 `WAIT_START`。
- 发送 `TARGET_LOCKED` 和 `STATUS`。

**返回值：** 无。

---

### `DeliveryController.road_center(line_result, cross_result)`

**作用：** 选择数字左右判断使用的道路分界位置。

**优先级：**

1. 已确认路口的 `center_x_norm`。
2. 有效巡线的 `decision_center_x_norm`。
3. `DEFAULT_CENTER_X_NORM`。

**参数：**

- `line_result`：巡线结果字典。
- `cross_result`：路口结果字典。

**返回值：** `float`，一般在 `0.0～1.0`。

---

### `DeliveryController.update_direction_votes(detections, line_result, cross_result)`

**作用：** 对 3～8 号目标更新左右方向投票。

**参数：**

- `detections`：数字框列表。
- `line_result`：巡线结果。
- `cross_result`：路口结果。

**行为：**

- 目标为 1 或 2 时直接返回，不使用视觉方向票。
- 选择道路分界后调用 `DirectionVoter.add()`。

**返回值：** 无。

---

### `DeliveryController.fixed_direction()`

**作用：** 查询 1、2 号当前路口的固定方向。

**使用：**

```python
fixed_route_direction(
    target_number,
    intersection_index,
    FIXED_ROUTES,
)
```

**返回值：** `LEFT`、`RIGHT` 或 `UNKNOWN`。

---

### `DeliveryController.decide_direction()`

**作用：** 在 `DECIDE_DIRECTION` 状态形成最终转向命令。

**逻辑：**

- 目标为 1、2：查询固定路线。
- 目标为 3～8：读取方向投票结果。
- 方向有效：状态进入 `WAIT_TURN_DONE`，发送一次 `TURN_DECISION`。
- 方向未知：只发送一次 `VISION_HOLD`，请求停车继续识别。

**路口序号：** 转向包发送后 `intersection_index += 1`。

**返回值：** 无。

---

### `DeliveryController.process_frame()`

**作用：** 处理一整帧，是总控最重要的方法。

**执行顺序：**

1. 读取和处理 UART。
2. 摄像头读取一次 `model_img`。
3. 生成 RGB `320×240` 的 `vision_img`。
4. 根据状态和帧号决定是否运行 YOLO。
5. `CAPTURE_TARGET`：只更新启动目标。
6. `WAIT_START`：等待指令，不发巡线包。
7. 其他状态：执行巡线和路口检测。
8. 在允许状态下发送巡线包。
9. 更新方向投票。
10. 更新路口消失和重新武装状态。
11. 路口确认时触发方向决策。
12. 按间隔刷新显示。

**参数：** 无。

**返回值：** 无。

---

### `DeliveryController.run()`

**作用：** 发送初始状态，然后进入主循环。

**循环：**

```python
while not app.need_exit():
    self.process_frame()
    time.sleep_ms(1)
```

**返回值：** 正常运行时不会返回，直到应用退出。

---

### `main()`

**作用：** 创建 `DeliveryController` 并调用 `run()`。

**返回值：** 无。

# 4. `yolov8_num_detect.py`：数字检测

## 4.1 文件职责

- 加载 YOLOv8 `.mud` 模型。
- 把 MaixPy YOLO 对象转换为普通 Python 字典。
- 解析数字标签。
- 提供独立模型调试入口。

该文件不负责多帧投票，也不直接决定左转或右转。

## 4.2 配置变量

### `MODEL_PATH`

```python
MODEL_PATH = "/root/models/yolov8_num_detect_v2.mud"
```

模型在 MaixCAM 文件系统中的路径。

### `CONFIDENCE_THRESHOLD`

```python
CONFIDENCE_THRESHOLD = 0.4
```

YOLO 检测最低置信度。降低会增加检出，也会增加误检；提高会减少误检，也可能漏掉远处数字。

### `IOU_THRESHOLD`

```python
IOU_THRESHOLD = 0.45
```

YOLO NMS 的 IoU 阈值，控制重叠框抑制。

## 4.3 函数和类

### `parse_room_number(label)`

**作用：** 从模型标签中解析一个 `1～8` 的房间号。

**参数：**

- `label`：字符串或可转换成字符串的对象。

**规则：** 标签中必须恰好有一个数字字符，并且该数字在 1～8。

示例：

```text
"5"      → 5
"room5"  → 5
"10"     → None
"digit"  → None
"0"      → None
```

**返回值：** `int` 或 `None`。

---

### `DigitDetector.__init__(model_path=MODEL_PATH, dual_buff=False)`

**作用：** 加载 YOLOv8 模型。

**参数：**

- `model_path=MODEL_PATH`：模型路径，默认 `/root/models/yolov8_num_detect_v2.mud`。
- `dual_buff=False`：是否启用双缓冲。

**正式总控：** 使用 `False`，保证当前结果和当前输入帧同步。

**独立调试：** 使用 `True`，提高吞吐。

---

### `DigitDetector.input_width()`

返回模型输入宽度，类型为整数。

### `DigitDetector.input_height()`

返回模型输入高度，类型为整数。

### `DigitDetector.input_format()`

返回模型要求的 MaixPy 图像格式。

以上三个方法用于创建匹配模型的摄像头。

---

### `DigitDetector.detect(img, conf_th=CONFIDENCE_THRESHOLD, iou_th=IOU_THRESHOLD)`

**作用：** 执行 YOLO 并标准化结果。

**参数：**

- `img`：模型尺寸和格式的 `maix.image.Image`。
- `conf_th`：置信度阈值，默认 0.4。
- `iou_th`：NMS IoU 阈值，默认 0.45。

**返回值：** 检测字典列表：

```python
[
    {
        "number": 5,
        "class_id": 4,
        "label": "5",
        "score": 0.87,
        "x": 40,
        "y": 60,
        "w": 30,
        "h": 45,
        "cx": 55.0,
        "cy": 82.5,
        "cx_norm": 0.172,
        "cy_norm": 0.344,
        "w_norm": 0.094,
        "h_norm": 0.188,
    }
]
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `number` | 解析后的病房号 |
| `class_id` | 模型类别下标，不一定等于病房号 |
| `label` | 模型原始标签 |
| `score` | 检测置信度 |
| `x/y` | 框左上角像素坐标 |
| `w/h` | 框宽高 |
| `cx/cy` | 框中心像素坐标 |
| `cx_norm/cy_norm` | 框中心归一化坐标 |

# 5. `delivery_logic.py`：纯决策逻辑

## 5.1 文件职责

该文件不导入 `maix`、`cv2` 或硬件模块，因此可以在电脑上直接测试。它负责：

- 数字框合法性过滤。
- 重复框去除。
- 同一行数字选择。
- 启动目标多帧锁定。
- 左右方向多帧加权投票。
- 固定路线查询。
- 去程状态机。

## 5.2 常量

方向：

```text
LEFT = "LEFT"
RIGHT = "RIGHT"
UNKNOWN = "UNKNOWN"
```

状态：

```text
CAPTURE_TARGET
WAIT_START
FOLLOW_LINE
DECIDE_DIRECTION
WAIT_TURN_DONE
```

## 5.3 内部函数

### `_iou(first, second)`

**作用：** 计算两个检测框的交并比 IoU。

**参数：** 两个含 `x/y/w/h` 的字典。

**返回值：** `float`，范围 `0.0～1.0`。

- `0`：不重叠。
- 越接近 `1`：两个框越相似。

---

### `_center_distance(first, second)`

**作用：** 计算两个框归一化中心的欧氏距离。

**参数：** 两个含 `cx_norm/cy_norm` 的字典。

**返回值：** `float`。

---

### `deduplicate_detections(detections, min_score=0.45, iou_threshold=0.55, center_threshold=0.035)`

**作用：** 过滤无效框并删除同一数字的重复框。

**参数：**

- `detections`：数字检测列表。
- `min_score=0.45`：最低置信度。
- `iou_threshold=0.55`：同类框达到该 IoU 视为重复。
- `center_threshold=0.035`：同类框中心过近也视为重复。

**过滤条件：**

- 数字必须为 1～8。
- 分数不能低于阈值。
- 宽高必须大于 0。
- 中心归一化坐标必须在 0～1。

**去重规则：** 先按置信度从高到低处理，重复时保留高分框。

**返回值：** 去重后的检测列表。

---

### `_same_row(detection, row, max_vertical_gap)`

**作用：** 判断某个数字框是否与已有数字组处于同一行。

**参数：**

- `detection`：待判断框。
- `row`：已有框列表。
- `max_vertical_gap`：默认纵向距离上限。

**判断：** 结合中心纵坐标差和平均框高动态计算允许距离。

**返回值：** `bool`。

---

### `select_digit_row(detections, min_score=0.45, max_vertical_gap=0.09, row_y_range=None)`

**作用：** 从画面中选择最可能属于路口标志的一行数字。

**参数：**

- `detections`：全部数字框。
- `min_score=0.45`：最低置信度。
- `max_vertical_gap=0.09`：同一行默认最大纵向归一化距离。
- `row_y_range=None`：可选纵向 ROI，格式 `(y_min, y_max)`。

**流程：**

1. 去重和过滤。
2. 可选按纵向 ROI 过滤。
3. 根据 `cy_norm` 分行。
4. 对每行计算分数。
5. 数量为 2～4 的行增加 0.6 分。
6. 选择“额外分 + 置信度总和”最高的一行；总分相同时，数字较多的行优先。
7. 按 `cx_norm` 从左到右排序。

**返回值：** 排序后的数字框列表；没有候选时返回 `[]`。

**调整建议：** 背景数字容易被选中时，可以在调用中增加 `row_y_range`，或调小 `max_vertical_gap`。

## 5.4 `TargetLocker`：目标卡牌锁定

### 构造参数

```python
TargetLocker(
    window_size=7,
    min_votes=5,
    min_score=0.55,
    roi=(0.20, 0.10, 0.80, 0.90),
    min_vote_margin=2,
)
```

| 参数 | 含义 |
| --- | --- |
| `window_size` | 保存最近多少帧 |
| `min_votes` | 获胜数字至少需要多少票 |
| `min_score` | 启动卡牌最低置信度 |
| `roi` | 卡牌归一化有效区域 |
| `min_vote_margin` | 第一名至少领先第二名多少票 |

### 成员变量

- `samples`：固定长度 `deque`，元素是数字或 `None`。
- `locked_target`：已锁定数字；未锁定时为 `None`。

### `reset()`

清空历史和目标。返回值为 `None`。

### `update(detections)`

**作用：** 用一帧检测结果更新目标投票。

**规则：**

- 只保留 ROI 内且达到 `min_score` 的框。
- 一帧必须恰好有一个候选数字才投票。
- 多框、无框或冲突时添加 `None`。
- 满足票数和领先差后锁定。
- 锁定后后续调用始终返回锁定值，直到 `reset()`。

**返回值：**

- 尚未锁定：`None`。
- 已锁定：目标数字 `1～8`。

## 5.5 `DirectionVoter`：左右方向投票

### 构造参数

```python
DirectionVoter(
    window_size=8,
    min_samples=4,
    dead_zone=0.07,
    min_winner_score=2.2,
    min_score_margin=0.8,
    min_detection_score=0.45,
)
```

| 参数 | 含义 |
| --- | --- |
| `window_size` | 最近方向样本窗口长度 |
| `min_samples` | 最少有效方向样本数 |
| `dead_zone` | 道路中心左右死区宽度 |
| `min_winner_score` | 胜方最低置信度总分 |
| `min_score_margin` | 胜方至少领先另一方的分数 |
| `min_detection_score` | 数字框最低置信度 |

### `clear()`

清空方向历史。返回值为 `None`。

### `add(detections, target_number, road_center_x_norm)`

**作用：** 加入一帧方向判断。

**参数：**

- `detections`：本帧数字框。
- `target_number`：目标病房号。
- `road_center_x_norm`：道路左右分界。

**流程：**

1. 选择最可信的一行数字。
2. 在该行寻找目标号。
3. 目标不存在或中心不可用：添加无效样本。
4. 目标在中心死区：添加无效样本。
5. 目标在分界左边：添加 `(LEFT, score)`。
6. 目标在分界右边：添加 `(RIGHT, score)`。

**返回值：** 本帧的 `LEFT`、`RIGHT` 或 `UNKNOWN`。这不是最终方向。

### `scores()`

**返回值：** 二元组：

```python
(
    {LEFT: left_score, RIGHT: right_score},
    {LEFT: left_count, RIGHT: right_count},
)
```

### `decision()`

**作用：** 根据整个窗口决定最终方向。

**必须同时满足：**

- 有效样本数不少于 `min_samples`。
- 胜方分数不少于 `min_winner_score`。
- 胜方领先分数不少于 `min_score_margin`。

**返回值：** `LEFT`、`RIGHT` 或 `UNKNOWN`。

## 5.6 `fixed_route_direction(target_number, route_index, routes)`

**作用：** 查询固定病房路线。

**参数：**

- `target_number`：目标号。
- `route_index`：当前路口下标。
- `routes`：固定路线字典。

**返回值：**

- 配置有效：`LEFT` 或 `RIGHT`。
- 目标、下标或方向无效：`UNKNOWN`。

## 5.7 `DeliveryStateMachine`：去程状态机

### 成员变量

| 变量 | 含义 |
| --- | --- |
| `state` | 当前状态字符串 |
| `target_number` | 已锁定目标号 |
| `crossroad_armed` | 是否允许新路口触发 |
| `waiting_for_clear` | 是否正在等待旧路口消失 |
| `clear_frames` | 路口连续消失帧数 |
| `last_direction` | 最近锁定方向 |
| `clear_frames_required` | 重新武装所需消失帧数，默认 3 |

### `reset()`

回到 `CAPTURE_TARGET`，清空目标和路口状态。无返回值。

### `lock_target(target_number)`

只有当前处于 `CAPTURE_TARGET` 且数字在 1～8 时成功。

**成功后：** 状态变成 `WAIT_START`。

**返回值：** `bool`。

### `start()`

只有 `WAIT_START` 且已有目标时成功。

**成功后：** 状态变成 `FOLLOW_LINE`，路口重新武装，并清除等待旧路口消失的计数。

**返回值：** `bool`。

### `stop()`

- 有目标：进入 `WAIT_START`。
- 无目标：进入 `CAPTURE_TARGET`。
- 路口重新武装，清除旧路口消失计数，并把 `last_direction` 恢复为 `UNKNOWN`。

无返回值。

### `trigger_crossroad()`

只有 `FOLLOW_LINE` 且路口已武装时成功。

**成功后：**

- 取消路口武装。
- 状态变成 `DECIDE_DIRECTION`。

**返回值：** `bool`。

### `lock_direction(direction)`

只有 `DECIDE_DIRECTION` 且方向为左右之一时成功。

**成功后：** 状态变成 `WAIT_TURN_DONE`。

**返回值：** `bool`。

### `turn_done()`

只有 `WAIT_TURN_DONE` 时成功。

**成功后：**

- 状态回到 `FOLLOW_LINE`。
- 开始等待旧路口消失。
- 仍不允许立即触发新路口。

**返回值：** `bool`。

### `update_crossroad_visibility(present)`

**参数：**

- `present`：当前帧是否存在路口。

**作用：** 转弯后统计路口连续消失帧数。达到阈值后重新武装。

**返回值：** 当前 `crossroad_armed` 值。

# 6. `track_line.py`：巡线检测

## 6.1 文件职责

- 使用 MaixPy `find_blobs()` 在多个 ROI 中寻找道路中心线色块。
- 拟合道路中心线。

## 6.2 配置变量

### 图像和目标位置

```python
IMAGE_WIDTH = 320
IMAGE_HEIGHT = 240
IMAGE_CENTER_X = 160
```

### 线色和 LAB 阈值

```python
LINE_COLOR = "black"
BLACK_THRESHOLD = [[0, 30, -128, 127, -128, 127]]
RED_THRESHOLD = [[0, 80, 40, 80, 0, 80]]
```

LAB 格式：

```text
[L_MIN, L_MAX, A_MIN, A_MAX, B_MIN, B_MAX]
```

红线阈值只是参考初值，必须按现场灯光标定。

```python
ROIS = [
```

每个 ROI 格式：


- 第一个 ROI 更远、更窄。

```text
MIN_PIXELS = 25
MIN_AREA = 25

```

- `MIN_PIXELS/MIN_AREA`：过滤太小的噪声。

```python
UART_DEVICE = "/dev/ttyS1"

```

正式总控不用这里的旧协议。独立调试默认也不占 UART；只有把 `ENABLE_SERIAL` 改为 `True` 后，独立入口才会映射 A19/A18 并打开 UART1。

## 6.3 函数和类

### `clamp(value, low, high)`

将数值限制在 `[low, high]`。返回限制后的值。

### `line_threshold(line_color)`

根据 `"black"/"red"` 返回对应 LAB 阈值列表；非法值抛出 `ValueError`。

### `setup_uart()`

`ENABLE_SERIAL=False` 时返回 `None`；否则打开 UART1 并返回 `uart.UART`。

### `choose_blob(blobs, expected_x, roi_width)`

**作用：** 从一个 ROI 的色块中选择最可能是道路中心线的色块。

**评分：**

```text
score = pixels - |blob.cx - expected_x| × 0.8
```

面积大且靠近预测位置的色块优先。

**返回值：** 最佳 `Blob`；没有合格色块时返回 `None`。

### `detect_line(img, expected_x, threshold)`

**作用：** 在每个 ROI 中寻找一个道路色块中心。

**返回值：**

```python
[(x, y, blob), ...]
```

可能返回 0、1 或 2 个点。

### `fit_line(points)`

**作用：** 用检测点拟合：

```text
x = slope × y + intercept
```

**返回值：**

```python
(x_bottom, angle, x_top, line_top_y)
```

- `x_bottom`：道路中心在 `TARGET_Y` 处的 x。
- `angle`：道路相对图像竖直方向的角度表达。
- `x_top`：道路中心在上方 ROI 的 x。
- `line_top_y`：上方点 y。

没有点时返回 `None`。只有一个点时角度返回 0。

### 构造参数

对应源码签名 `LineTracker(line_color=LINE_COLOR, filter_alpha=FILTER_ALPHA)`：

- `line_color=LINE_COLOR`：黑线或红线，当前默认 `"black"`。

把道路预测位置恢复到画面中心，清空滤波状态。无返回值。

### `process(img)`

**参数：** RGB `320×240` MaixPy 图像。

**返回值：**

```python

    "valid": True,
    "error": -12.5,
    "angle": 3.2,
```

# 7. `crossroad_detect_v2.py`：正式十字路口检测

## 7.1 文件职责

正式算法使用 MaixPy `find_blobs()`，不依赖 OpenCV：

1. 在上下两个水平 ROI 中分别找前进方向线的色块中心，连接成近似竖直线。
2. 在左右两个竖直 ROI 中分别找横向道路线的色块中心，连接成近似水平线。
3. 检查两条线各自的斜率，并计算交点和夹角。
4. 过滤夹角不足、交点越界或离画面中心过远的结果。
5. 连续多帧确认路口，并对交点做低通滤波。

## 7.2 关键配置变量

### 图像和线色

```text
IMAGE_WIDTH = 320
IMAGE_HEIGHT = 240
LINE_COLOR = "black"
BLACK_THRESHOLD = [[0, 30, -128, 127, -128, 127]]
RED_THRESHOLD = [[0, 80, 40, 80, 0, 80]]
```

`LINE_COLOR` 支持 `"black"` 和 `"red"`；正式总控会把自己的同名配置传给检测器。红线 LAB 阈值只是参考初值，必须现场标定。

### 四个 ROI

```python
V_ROI_TOP = [110, 50, 100, 30]
V_ROI_BOTTOM = [80, 160, 160, 40]
H_ROI_LEFT = [80, 80, 30, 80]
H_ROI_RIGHT = [210, 80, 30, 80]
```

- 上下 ROI 用于拟合前进方向的近似竖直线。
- 左右 ROI 用于拟合横向道路的近似水平线。

### 色块和几何筛选

```text
MIN_PIXELS = 20
MIN_AREA = 20
MAX_BLOB_WIDTH_RATIO = 0.70
MAX_BLOB_HEIGHT_RATIO = 0.70
MAX_V_SLOPE = 0.577
MAX_H_SLOPE = 0.577
MIN_CROSS_ANGLE = 45°
MAX_CROSS_CENTER_DIST = 120
FILTER_ALPHA = 0.4
```

色块过小、过宽或过高会被过滤；两条拟合线斜率、夹角或交点位置不合理时不会报告十字路口。

### 连续帧

```text
CROSS_CONFIRM_FRAMES = 3
CROSS_LOST_FRAMES = 3
```

- 连续 3 帧检测到后确认。
- 连续 3 帧丢失后取消确认。

### 独立调试配置

```text
ENABLE_SERIAL = False
UART_DEVICE = "/dev/ttyS1"
UART_BAUDRATE = 115200
```

这些变量只控制 `crossroad_detect_v2.py` 的独立调试显示和旧串口输出；正式总控不调用其中的 `main()`、`setup_uart()` 或 `send_serial()`。

## 7.3 函数

### `line_threshold(line_color)`

返回黑线或红线 LAB 阈值；非法值抛出 `ValueError`。

### `choose_blob_v()` / `choose_blob_h()`

从单个 ROI 中选择像素较多且靠近预测位置的色块，并过滤过宽或过高的大色块。

### `detect_vertical_line(img, expected_x, threshold=BLACK_THRESHOLD)`

在上下 ROI 中构造近似竖直线。成功返回：

```python
(x_top, y_top, x_bottom, y_bottom, top_blob, bottom_blob)
```

任一 ROI 无合格色块或斜率过大时返回 `None`。

### `detect_horizontal_line(img, expected_y, threshold=BLACK_THRESHOLD)`

在左右 ROI 中构造近似水平线。成功返回：

```python
(x_left, y_left, x_right, y_right, left_blob, right_blob)
```

任一 ROI 无合格色块或斜率过大时返回 `None`。

### `line_intersection(v_line, h_line)`

计算两条线的交点和 `0～90°` 夹角。成功返回 `(x, y, angle)`，无效时返回 `None`。

### 绘图与调试串口

- `draw_roi()`：绘制 ROI。
- `draw_blob()`：绘制色块和中心。
- `draw_extended_line()`：将检测线延长到画面边缘。
- `draw_result(img, result, fps=None)`：绘制完整调试结果。
- `setup_uart()`：独立调试 UART 初始化。
- `send_serial(serial_dev, result)`：发送旧版 `<Bhh>` 路口包，正式总控不调用。

## 7.4 `CrossroadDetector`

### 构造参数

对应源码签名 `CrossroadDetector(line_color=LINE_COLOR, filter_alpha=FILTER_ALPHA)`：

- `line_color`：`"black"` 或 `"red"`，当前默认 `"black"`。
- `filter_alpha`：交点低通滤波权重，当前默认 `0.4`。
- 构造时选择 LAB 阈值并调用 `reset()`。

### 状态变量

- `cross_count/lost_count/confirmed`：连续检测和确认状态。
- `expected_x/expected_y`：下一帧色块选择的预测位置。
- `filtered_cross_x/filtered_cross_y`：低通滤波交点。
- `filter_initialized`：滤波器是否已有有效交点。

### `reset()`

清空连续帧、预测位置和交点滤波状态。无返回值。

### `process(img)`

**参数：** RGB `320×240` MaixPy 图像。

**返回值：**

```python
{
    "detected": bool,
    "confirmed": bool,
    "x": int,
    "y": int,
    "center_x_norm": float or None,
    "angle": float,
    "score": float,
    "v_line": tuple or None,
    "h_line": tuple or None,
    "cross": tuple or None,
    "cross_count": int,
}
```

- `detected`：当前帧能否形成有效交点。
- `confirmed`：是否达到连续确认帧数。
- `x/y`：低通滤波后的当前交点；无交点时为 0。
- `center_x_norm`：滤波交点横坐标归一化值；无交点时为 `None`。
- `score`：两条检测线长度之和，当前总控不直接使用。
- `v_line/h_line/cross/cross_count`：独立调试绘图数据。

总控触发路口时要求 `detected` 和 `confirmed` 同时为真。

### `main()`

独立路口调试入口。

# 8. `vision_protocol.py`：UART 协议

## 8.1 帧格式

```text
AA 55 LEN TYPE PAYLOAD CHECKSUM
```

- 帧头：`AA 55`。
- `LEN`：`TYPE + PAYLOAD` 的长度。
- 最大 body 长度：64。
- 校验：从 `AA` 到 payload 最后一个字节的累加和低 8 位。

## 8.2 消息类型

STM32 → MaixCAM：

```text
START     = 0x01
RESET     = 0x02
STOP      = 0x03
TURN_DONE = 0x04
```

MaixCAM → STM32：

```text
TARGET_LOCKED = 0x81
LINE_DATA     = 0x82
TURN_DECISION = 0x83
VISION_HOLD   = 0x84
STATUS        = 0x85
```

方向编码常量：

```text
DIRECTION_LEFT  = 0
DIRECTION_RIGHT = 1
```

暂停原因：

```text
1 = 未找到目标
2 = 方向不确定
3 = 固定路线未配置
4 = 巡线丢失
```

当前总控实际使用原因 2 和 3；1、4 已预留。

## 8.3 编码函数

### `encode_frame(message_type, payload=b"")`

通用帧编码器。

**参数：** 消息类型整数和 bytes payload。

**返回值：** 完整 `bytes` 帧。

payload 太大时抛出 `ValueError`。

### `encode_target_locked(target_number)`

payload 格式 `<B`，返回目标锁定帧。

### `encode_line_data(valid, error, angle, center_x_norm)`

payload 格式：

```text
<BhhH
```

| 字段 | 类型 | 单位 |
| --- | --- | --- |
| valid | uint8 | 0/1 |
| error | int16 | 像素，当前直接四舍五入 |
| angle | int16 | 度 × 100 |
| center | uint16 | 归一化中心 × 1000 |

`center_x_norm` 编码前会限制到 `0～1000`；`error` 和 `angle×100` 当前没有额外限幅，必须保证调用方数值处于 int16 范围。返回完整 `LINE_DATA` 帧。

### `encode_turn_decision(direction, target_number=0, intersection_index=0, confidence=0)`

后三个参数在源码中默认均为 0。payload 格式 `<BBBB`：

- 方向：`LEFT/RIGHT` 分别编码为 `1/2`。
- 目标号：限制到 `0～255`。
- 路口序号：限制到 `0～255`。
- 置信度百分比：限制到 `0～100`。

方向不是左右时抛出 `ValueError`。

### `encode_vision_hold(reason)`

payload 格式 `<B`，返回暂停请求帧。

### `encode_status(state_code, detail=0)`

payload 格式 `<BB`，返回状态帧。

## 8.4 `FrameParser`

### 成员变量 `buffer`

`bytearray`，保存尚未组成完整帧的接收数据。

### `clear()`

清空接收缓存。

### `feed(data)`

**作用：** 把新收到的任意长度字节加入缓存，并尽量解析全部完整帧。

**能处理：**

- 帧头前噪声。
- 半包。
- 多帧粘包。
- 坏校验。
- 长度为 0。
- 异常超长 LEN。

**参数：** `bytes` 或空数据。

**返回值：**

```python
[
    (message_type, payload_bytes),
    ...
]
```

没有完整帧时返回 `[]`。

# 10. 参考文件

## 10.1 `crossroad_detect.py`

这是保留的 OpenCV/Hough 十字路口参考实现，不被正式总控导入。

它先生成黑线灰度或红线 HSV 掩膜，再用 `cv2.HoughLinesP()` 检测候选线段、两两计算交点。该版本可用于对比实验，但正式运行使用第 7 章的 `crossroad_detect_v2.py` 四 ROI 色块法。

## 10.2 `num_detact.py`

这是旧的单数字分类方案，不被正式总控导入。

### 思路

- 固定 ROI 裁剪数字。
- 灰度化和前景连通域提取。
- 缩放成类似 MNIST 的 `28×28` 输入。
- 使用 `nn.NN` 分类。
- 历史窗口投票。
- UART 发送稳定数字。

### 主要函数

- `setup_uart()`：打开 UART1。
- `crop_digit_foreground()`：提取最大前景。
- `resize_like_mnist()`：生成 `1×1×28×28` 输入。
- `preprocess_digit()`：完成 ROI 到模型输入的预处理。
- `softmax()`：将 logits 转概率。
- `check_model()`：检查模型输入结构。
- `predict_digit()`：执行分类。
- `update_stable_digit()`：历史投票。
- `send_digit_packet()`：发送旧数字协议。
- `main()`：独立分类流程。

### 与 YOLO 正式方案区别

旧方案只能对固定区域内一个数字分类，不直接提供多数字检测框，因此无法方便地处理一行两个或四个数字，也不能根据目标框横坐标判断左右。

# 12. 后续调整时从哪里改

## 12.1 YOLO 漏检数字

优先检查：

1. 模型路径和标签。
2. 摄像头焦距。
3. `yolov8_num_detect.py` 的 `CONFIDENCE_THRESHOLD`。
4. `delivery_logic.py` 的 `min_detection_score`。
5. 数字是否太小、模糊、倾斜或反光。

注意存在两层阈值：YOLO 首先过滤一次，方向逻辑还会再次过滤。

## 12.2 启动卡牌迟迟不能锁定

调整 `TargetLocker`：

- `min_score`。
- `window_size`。
- `min_votes`。
- `min_vote_margin`。
- `TARGET_ROI`。

先观察屏幕检测框，不要直接大幅降低所有阈值。

## 12.3 左右判断反复变化

调整 `DirectionVoter`：

- 增大 `window_size`。
- 增大 `min_samples`。
- 增大 `dead_zone`。
- 增大 `min_score_margin`。

同时检查道路中心是否稳定，以及摄像头是否松动。

## 12.4 小车还没到路口就触发

检查 `crossroad_detect_v2.py`：

- 调整四个 ROI，避免背景黑块或红色物体同时进入对应区域。
- 提高 `MIN_PIXELS/MIN_AREA`。
- 减小 `MAX_BLOB_WIDTH_RATIO/MAX_BLOB_HEIGHT_RATIO`。
- 减小 `MAX_V_SLOPE/MAX_H_SLOPE`。
- 提高 `MIN_CROSS_ANGLE`。
- 减小 `MAX_CROSS_CENTER_DIST`。
- 增大 `CROSS_CONFIRM_FRAMES`。

## 12.5 路口漏检

可以反向调整以上参数，同时检查：

- 线色配置是否正确。
- 黑线或红线 LAB 阈值。
- 横线是否完整进入 ROI。
- 相机俯视角度。

## 12.6 巡线抖动

- 降低 `FILTER_ALPHA`。
- 提高 `MIN_PIXELS/MIN_AREA`。
- 调整 `ROIS`。
- 检查宽色块过滤比例。

响应过慢时则适当提高 `FILTER_ALPHA`。

## 12.7 修改 1、2 号固定路线

编辑 `delivery_car_main.py`：

```python
FIXED_ROUTES = {
    1: [LEFT],
    2: [RIGHT],
}
```

数组按小车去程实际遇到的路口顺序填写。当前逻辑不支持 `STRAIGHT`；如果固定路线需要在某个已检测路口直行，应先扩展方向常量、协议和底盘逻辑，不能用空值代替。

## 12.8 性能不足

按优先级尝试：

1. 增大 `DISPLAY_EVERY_N_FRAMES`。
2. 增大 `YOLO_EVERY_N_FRAMES`。
3. 增大 `LINE_PACKET_EVERY_N_FRAMES`。
4. 适当增大四个 ROI 的 `find_blobs()` 步长，或缩小 ROI 面积。
5. 正式比赛关闭不需要的调试绘制。

不要在总控模式打开 YOLO 双缓冲，除非已经解决检测结果与当前帧坐标错位的问题。

# 13. 推荐调试顺序

1. 单独运行 `yolov8_num_detect.py`，确认 1～8 标签和框坐标。
2. 单独运行 `track_line.py`，标定黑线/红线阈值和 ROI。
3. 单独运行 `crossroad_detect_v2.py`，标定黑/红 LAB 阈值、四个 ROI 和色块/几何筛选参数。
4. 在电脑运行 `test_delivery_logic.py`，确保纯逻辑仍通过。
5. STM32 单独测试 UART 帧收发。
6. 运行 `delivery_car_main.py`，先不启动车轮，观察状态转换和发送包。
7. 低速测试巡线。
8. 低速测试一个路口的数字决策、停车和 `TURN_DONE`。
9. 最后测试完整去程。

# 14. 当前限制和下一步

当前已经实现：

- 单目标卡牌锁定。
- 去程巡线和路口检测。
- 3～8 号实时数字左右判断。
- 1、2 号固定路线入口。
- 多帧容错和路口去重。
- UART 双向状态控制。

当前尚未完整实现：

- `STRAIGHT` 路口指令。
- 到达病房的视觉停车判断。
- 卸药或取药流程。
- 掉头流程。
- 返程路线栈。
- T 字路口和十字路口的明确分类。
- UART 超时和 STM32 掉线检测。
- 实车参数的最终标定值。

后续改进时，建议保持以下边界：

- YOLO 文件只输出检测数据。
- 巡线文件只输出道路数据。
- 路口文件只输出路口数据。
- `delivery_logic.py` 负责纯判断。
- `delivery_car_main.py` 负责编排流程。
- STM32 负责电机闭环和动作完成反馈。
